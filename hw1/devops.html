DevOps (Agile, extended)

Why it’s an extension, not a replacement

Agile emphasizes collaboration between developers and product management — DevOps includes the operations team. Atlassian

DevOps was created to fill in some missing gaps in the Agile methodology. TechRepublic

Origin story

2007: while consulting on a data center migration for the Belgium government, system administrator Patrick Debois becomes frustrated by conflicts between developers and system admins. New Relic

2008: at the Agile Conference in Toronto, Andrew Schafer posted an offer to moderate an ad hoc “Birds of a Feather” meeting to discuss the topic of “Agile Infrastructure.” Only one person showed up to discuss the topic: Patrick Debois. DevOps.com

June 2009: John Allspaw and Paul Hammond gave a talk entitled “10+ Deploys a Day: Dev and Ops Cooperation at Flickr.” BMC

October 2009: Debois started DevOpsDays. He later explained the name: “I picked ‘DevOpsDays’ as Dev and Ops working together because ‘Agile System Administration’ was too long.” New Relic

What it is

DevOps brings together the development and operations groups for a faster, more accurate, and more responsive software delivery experience. Simplilearn

CI/CD (continuous integration and continuous delivery): Continuous integration means building and regularly validating the project by updating code changes at set intervals. Continuous delivery builds off CI by automatically deploying code in the production environment. Simplilearn

How success is measured

DORA (DevOps Research and Assessment) is a research team that Google acquired in 2018. Wrike

It identified four key metrics, namely Deployment Frequency (DF), Lead Time for Changes (LT), Mean Time to Restore (MTTR), and Change Failure Rate (CFR). Opsera
